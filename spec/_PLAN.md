- **第一原则**（core.md）：崩溃背景 + 简洁实用 + 宁缺毋滥；结构 L1-Ln 仅参考，不死板逐级。
- **红线**：不写人、不视人为威胁；可写自我保护（低调、减少暴露、避免冲突），不把他人刻画为威胁对象。
- **非城市场景**：崩溃后野外 / 丛林 / 山区是原始生存理想区域，为默认视角之一。
- **药品与可自制资源**：之初搜集常见药品及用途；不需现代工业能做出来的资源要记入 + 写核心制作步骤（如木炭）。
- **崩溃测试自检**：孤立无援、叫不到帮助的人看完能不能立刻用？不能就不收或重写。
- **深度可操作**（2026-09-19 新增，与第一原则同级）：目标读者是**非专业普通人**，照着做就能完成目标；简洁之外**深度要够、不流于形式**；**删「正确的废话」**——不写「注意保暖」「保持清洁」这类正确但无操作价值的句子，改写成「裹到什么程度、用什么、多久换一次」。每一步落到「手怎么动、用什么料、做到什么程度算成」。
- **逐节点审核**（2026-09-19 新增）：每完成一个节点，重读 `spec/core.md` + 本规划 + 创作约束审核一遍，再进下一个（防多轮摘要丢失 core 约束）。
- **区域划分**（2026-09-19 新增，用户明确）：内容不再限定于 `capabilities/`。顶层按原规划（《文件组织规范》§40）分两个区域——`capabilities/`（知识主树）+ `scenarios/`（场景/整合主题组合入口，不建第二套 Level、不复制能力知识）。场景节点（如 [[越冬]]、[[非城市场景]]）放 `scenarios/`。
- **口吻**：命令式清单，篇幅精简；删「来源」节、「为什么」节；关键原理压进「注意」或一句话导语。
- **清和平假设**：报警 / 报修 / 送医 / 求救 / 官方指示 / 公共供水点 / 维修人员等「可依赖解法」一律去掉——「没有」是前提不是假设。
- **校验清单**：front matter 四件（filename/title/level/category/status）齐全；title 全库唯一且与 H1 一致；level 与目录一致；Wikilink 能解析（index 里的待建链接是预告清单，不是死链，不要批量"修"）。
- **每轮自检命令**（脚本已入库，2026-09-19 起）：
  ```
  python3 spec/scripts/check.py --brief    # 结构错误 / 文件与链接总数
  python3 spec/scripts/check.py --stale    # 「（方向）／尚未展开」但目标已建的过期标注
  python3 spec/scripts/check.py --shallow  # 浅句候选（只有告诫、没有操作），人工复核
  ```
  未解析链接全部列出、不算错误（index 里的属预告清单）；真正要清零的是 `结构错误` 与 `过期标注` 两项。
- **阶段2 验收标准（2026-09-19 定）**：不看 Level 表填得多满，只看**抽一条出来，非专业的人能不能照着动手**——有没有材料、有没有量、做到什么程度算成。做不到就补，而不是"这级还没建完"就新建节点。
- **front matter 格式（2026-09-19 踩坑）**：`meta:` 下各键**顶格写、不缩进**，与全库一致；缩进写法会让校验脚本的 `^title:`/`^filename:` 匹配静默失效（误判为"0 错误"）。新建节点后先看一眼前 11 行确认。
